# IAM scenarios for prospective LCA

An interactive, browser-native workshop from PSI's Laboratory for Energy
Systems Analyses. The presentation introduces IAM theory, RCPs, SSP–RCPs and
the CMIP7 emission-family framework. It first connects human needs, energy
services, greenhouse-gas emissions, cumulative CO₂ and warming, then follows
scenario evidence through `premise` transformations to prospective inventories
and LCIA.

## Presentation

The dashboard includes:

- an anonymous four-future evidence screen with staged label reveal;
- the core IMAGE quartet `SSP1-L`, `SSP2-VLHO`, `SSP2-M`, and `SSP3-H`;
- controlled comparisons that change policy ambition or IAM model, never both;
- four climate-and-energy motivation states and an explicit rationale for IAMs;
- a sourced net-zero target-year map and an explicit pledge → pathway → investment → inventory bridge;
- a definition of IAMs plus a policy-history timeline from IS92 to CMIP7;
- six core chapters with 31 presenter states (a 75-minute speaking plan), plus
  21 clearly marked backup states;
- theory views for IAM boundaries, stocks and flows, model structure and limitations;
- ten IMAGE energy-accounting states covering primary, secondary and final energy, four end-use transformations and their premise mappings;
- the AR5 → AR6 → AR7 terminology bridge and seven CMIP7 emission families;
- an applied CH → IMAGE WEU geography map, distinct from the WEU+CEU teaching aggregation;
- one sector explorer for electricity, passenger cars, cement and steel;
- coordinated annual-removal, cumulative-removal and temperature views for overshoot;
- an evidence-status matrix showing which scenario dimensions `premise` can transform;
- scenario-specific LCIA scores in their declared functional units, with deployment context and contribution evidence;
- an interactive result tracer that keeps case, scenario, year and indicator synchronized from the IAM signal through premise mapping, LCIA trajectory and contribution evidence; and
- applied steel, photovoltaic, system trade-off, evidence-audit and case-library states that connect IAM evidence to premise transformations and LCA interpretation.

The dashboard never invents LCIA scores: it reads the validated aggregated
results and contribution records generated by the repository scripts.

## Run locally

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python app.py
```

Open <http://127.0.0.1:8050>. Use the visible Back, Reveal, and Next controls.
The live Next sequence stops at the end of the 31-slide core. Compact detail
buttons open related backup slides and remember their origin; every backup slide
has a **Return to original slide** button. The **Backup** chapter in the header
also exposes the complete appendix directly.
The footer's **Export PDF** button prepares all presenter states, reveals the
anonymous scenario labels, and opens the browser print dialog with a 16:9 PDF
layout. The PDF retains all 52 core and backup states. Interactive slides use
their currently selected state in the export.

For a production-like local run:

```bash
.venv/bin/gunicorn app:server --bind 127.0.0.1:8050 --workers 1 --threads 4
```

## Data pipeline

The original consolidated CSV is deliberately ignored by Git:

```text
data/raw/structured_data (2, 4, 4) + GCAM 2026.csv
```

Build the curated workshop derivative with:

```bash
python3 scripts/build_workshop_data.py
python3 scripts/validate_workshop_data.py
```

This creates `data/processed/workshop_pathways.csv.gz`. It contains the four
IMAGE teaching pathways at native IMAGE regions and World-level comparison rows
for all six IAMs. The builder retains source values, adds explicit display
values and units, and does not fill absent rows. Model-specific unit conversions
are encoded explicitly because the consolidated source file has no unit column.

`data/region_mapping.json` records the R10 mapping-quality contract, while
`data/image_region_mapping.json` and `data/remind_eu_region_mapping.json`
record the applied geographies used in the deck: a Swiss inventory location
maps to IMAGE WEU but REMIND-EU NEN; WEU+CEU is a separate teaching aggregation
used only where explicitly labelled. Scenario narratives and transformation
metadata live in `data/narratives.json` and `data/premise_transformations.json`.

The energy-accounting slides use a small, auditable extract from the original
IMAGE 3.4 workbooks. Rebuild it with the `premise-2.4.6` environment:

```bash
conda run -n premise-2.4.6 python scripts/extract_image_energy_layers.py \
  "/path/to/image 3.4"
conda run -n premise-2.4.6 python scripts/extract_image_electricity_chain.py \
  "/path/to/image 3.4"
conda run -n premise-2.4.6 python scripts/extract_image_total_energy_chain.py \
  "/path/to/image 3.4"
conda run -n premise-2.4.6 python scripts/extract_image_end_use_transformations.py \
  "/path/to/image 3.4"
conda run -n premise-2.4.6 python scripts/extract_premise_mapping_counts.py \
  "/path/to/premise/iam_variables_mapping" --premise-version 2.4.6
```

This creates `data/processed/image_energy_layers.csv` with selected World and
Europe (`WEU + CEU`) primary-energy, secondary-electricity and final-energy
series. Every aggregate retains its source regions, variable names and workbook
identifier. It also creates `data/processed/image_electricity_chain_example.csv`,
the auditable SSP2-VLHO European electricity example used in the Sankey slide;
energy-service values retain their original passenger-km unit and are not drawn
as EJ-wide flows.

The total-energy extractor creates `data/processed/image_total_energy_chain.csv`
for the matched World whole-system Sankeys. It contains a final-energy
carrier-by-sector matrix, allowing electricity, liquids, gases, solids/biomass,
heat and hydrogen to appear as explicit Sankey nodes. Because the IMAGE
workbooks do not expose a single aggregate secondary-energy total, gross
secondary indicators remain separately labelled rather than summed into a
fabricated total.

The end-use extractor creates
`data/processed/image_end_use_transformations.csv` for IMAGE 3.4 SSP2-VLHO.
It pairs powertrain, kiln, steel-route and heating-carrier mixes with explicit
specific-energy calculations. Every row records its source variables and
derivation; the cement indicator is labelled as a non-metallic-minerals sector
proxy, and heating is expressed per person because this IMAGE export contains
neither useful heat nor floor area.

`data/processed/premise_mapping_counts.csv` records the number of distinct IAM
variable strings referenced for each model and transformation sector in the
premise 2.4.6 mapping YAMLs. Counts include model-specific activity, efficiency
and energy-use aliases; they describe mapping granularity, not model quality.

## Building scenario databases and LCIA results

Use the `premise-2.4.6` environment and provide the encrypted IAM-data key
without committing it:

```bash
conda install -n premise-2.4.6 -c conda-forge \
  scikit-umfpack=0.3.3 numpy=1.26.4 scipy=1.13.1 setuptools=80.9.0
export PREMISE_KEY='<local key>'
conda run -n premise-2.4.6 python scripts/build_premise_databases.py --smoke --no-write
conda run -n premise-2.4.6 python scripts/build_premise_databases.py
conda run -n premise-2.4.6 python scripts/calculate_lcia_results.py
```

The build creates an isolated Brightway project based on ecoinvent 3.12 cutoff
and writes the four IMAGE scenarios for 2020, 2040 and 2060. The LCIA script computes
IPCC 2021 GWP100 including hydrogen and biogenic CO2, plus EF 3.1
minerals/metals, land and water indicators, for 1 kWh Swiss low-voltage
electricity, 1 vehicle-km from the WEU passenger-car transport market, 1 kg
Swiss unspecified cement, 1 kg WEU low-alloyed steel, and 1 kg CO2 captured and
stored with WEU solvent- and sorbent-based DAC. Exact activity keys, native
locations, units, database names and provenance are written with every score.
The deployed app never runs Brightway. The pinned `scikit-umfpack` build
accelerates repeated LCI solves on Apple Silicon; the calculation script
supplies a process-local compatibility shim for its removed NumPy test helper
and does not patch the installed package.

## Checks

The package-level smoke tests require only the dashboard environment:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

With the server running and Playwright available, capture and inspect every
presenter state at 1600×900:

```bash
python scripts/visual_check.py
```

The visual check exercises the anonymous label reveal, the consolidated sector
explorer, the applied result tracer, all chapter states and viewport-overflow
reporting.

## Heroku

The repository contains a `Procfile`, `.python-version`, and production
dependencies. After choosing an app name and authenticating with Heroku:

```bash
heroku create <app-name>
git push heroku main
heroku open
```

The health endpoint is `/health`.

## Design and scientific review

- `design/workshop_blueprint.md` contains the facilitation arc, evidence rules,
  and scenario-selection method.
- `design/dashboard_specification.md` defines the UI states and data contracts.
- `workshop_design_questionnaire.md` records the agreed audience, scope, and
  workshop decisions.

Narrative cards, unit mappings, technology groupings, R10 mappings and LCIA
interpretations require owner review before the workshop is treated as a
scientifically signed-off release.

## Repository policy

Do not commit proprietary IAM source workbooks, credentials, large raw files,
local environments, or unreviewed generated databases. The official PSI mark
in `assets/psi-mark.svg` is sourced from PSI's public website and should remain
subject to PSI brand guidance.
