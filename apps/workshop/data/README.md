# Data

The ignored `data/raw/structured_data (2, 4, 4) + GCAM 2026.csv` is the source
for the public teaching extract. Run `scripts/build_workshop_data.py` to create
`processed/workshop_pathways.csv.gz`; absent rows are not interpolated or filled.

`processed/remind_hydrogen_mechanics.csv` is the auditable, 27-row source for
the investment → output → efficiency example. It is extracted from the original
REMIND 3.5 `REMIND_generic_SSP2-PkBudg650.mif` with:

```bash
python scripts/extract_remind_mechanics.py /path/to/REMIND_generic_SSP2-PkBudg650.mif
```

The extract retains exact World-level values at reported five-year time steps;
it does not interpolate between periods.

`processed/image_energy_layers.csv` is the auditable source for the primary-,
secondary- and final-energy teaching sequence. It is extracted from four
original IMAGE 3.4 workbooks with:

```bash
conda run -n premise-2.4.6 python scripts/extract_image_energy_layers.py \
  "/path/to/image 3.4"
```

The 1,368 rows cover the four workshop scenarios for World and Europe
(`WEU + CEU`) at exact decadal time steps from 2020 to 2100. Aggregated groups
retain their contributing IMAGE regions, variable names and source workbook
identifier; the original workbooks are not copied into this repository.

`processed/image_electricity_chain_example.csv` is a 72-row, single-scenario
extract used for the Sankey example. It follows electricity in IMAGE 3.4
SSP2-VLHO for Europe (`WEU + CEU`) from primary inputs through conversion,
secondary output and selected final uses, and keeps passenger mobility in its
native `billion pkm/yr` service unit. Rebuild it with:

```bash
conda run -n premise-2.4.6 python scripts/extract_image_electricity_chain.py \
  "/path/to/image 3.4"
```

The service value is deliberately not scaled as an energy flow: it has a
different physical unit from the EJ/yr Sankey links.

`processed/image_total_energy_chain.csv` is a 243-row World extract for the
matched 2020/2060 whole-system Sankeys. It contains non-overlapping
primary-energy groups, selected reported secondary-carrier indicators and a
carrier-by-sector final-energy matrix covering electricity, liquids, gases,
solids/biomass, heat and hydrogen. Rebuild it with:

```bash
conda run -n premise-2.4.6 python scripts/extract_image_total_energy_chain.py \
  "/path/to/image 3.4"
```

The carrier nodes reconcile to reported final-energy use and represent energy
delivered to users; they are not gross secondary production. The IMAGE workbook
does not report one aggregate `Secondary Energy` row, so electricity,
liquid-fuel and hydrogen indicators remain separately labelled. Transport
carrier shares are scaled to reported passenger/freight totals, with the method
recorded in every affected row.

`processed/image_end_use_transformations.csv` is the 282-row World extract for
the passenger-car, cement, steel and space-heating zoom-ins under IMAGE 3.4
SSP2-VLHO. It pairs technology or route mixes with specific-energy and context
series from 2020 to 2100. Rebuild it with:

```bash
conda run -n premise-2.4.6 python scripts/extract_image_end_use_transformations.py \
  "/path/to/image 3.4"
```

Each derived row records its source variables and calculation. Cement uses an
explicit non-metallic-minerals energy-per-cement-output proxy because the source
workbook does not report populated kiln-energy values. Space heating uses
delivered energy per person because this export contains neither floor area nor
useful heat; electricity is labelled as a carrier-level technology proxy.

`processed/premise_mapping_counts.csv` is a 60-row audit of distinct IAM
variable strings referenced in premise 2.4.6 model-specific mapping aliases.
Rebuild it with:

```bash
conda run -n premise-2.4.6 python scripts/extract_premise_mapping_counts.py \
  "/path/to/premise/iam_variables_mapping" --premise-version 2.4.6
```

The count includes IAM activity, efficiency and energy-use aliases across ten
transformation sectors and six IAM model labels. It measures the granularity of
the current premise mapping files, not the overall detail or quality of an IAM.

`processed/lcia_results.csv` and `processed/lcia_contributions.csv` contain only
aggregated Brightway results and metadata, never proprietary ecoinvent datasets.
They are generated by `scripts/calculate_lcia_results.py` from the database set
recorded in `processed/premise_databases.json`. The sector-explorer GWP panel
uses the IPCC 2021 rows for Swiss low-voltage electricity, the WEU passenger-car
transport market, Swiss unspecified cement and WEU low-alloyed steel. The built
2020, 2040 and 2060 scenario databases are plotted; connecting lines are visual
guides rather than interpolated LCIA calculations. The four scenario-specific
2020 points nearly coincide because the pathways have not materially diverged.

When the explorer is switched to `Absolute`, the GWP panel multiplies those
regional per-unit results by IMAGE World activity after an explicit unit
conversion: `EJ electricity × kg CO₂-eq/kWh` and `Mt cement or steel × kg
CO₂-eq/kg` are reported as `Gt CO₂-eq/yr`. These are labelled
inventory-equivalent estimates because CH or WEU intensities are being applied
to World activity; they are not spatially resolved system-LCA totals. Passenger
cars remain unscaled because the curated IAM extract does not identify its
activity as vehicle-kilometres, which is the Brightway functional unit.

`image_region_mapping.json` records the IMAGE 3.4 country-to-region membership
used by premise 2.4.6. In the applied example, inventory location `CH` maps to
IAM region `WEU`. The `WEU + CEU` aggregation used on several teaching charts
is recorded separately and must not be interpreted as the premise mapping.

`remind_eu_region_mapping.json` records the 11 European regions represented in
the premise 2.4.6 REMIND-EU topology. The same inventory location `CH` maps to
`NEN` in REMIND-EU, illustrating that IAM geography is model-specific even when
the LCA activity location is unchanged.

The narrative, transformation, region and LCIA activity contracts are reviewed
source metadata for the dashboard. Owner scientific sign-off is still required
before public workshop delivery.
